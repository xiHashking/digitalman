# Material Workflow（发资料的强制流程）

## When to Use
当客户出现以下情况时调用此技能：
- **资料请求**：客户明确要求发送资料、产品说明书、解决方案或文档
- **资料获取**：客户需要产品说明书、条款等书面资料
- **链接获取**：客户希望获取产品的详细信息链接
- **二次发送**：客户表示之前发送的资料找不到/打不开/需要再发一次 
- **重点**：只能发送这个唯一pdf，其他的绝对不发

## 约束条件
- **真实性**：必须使用指定资料链接，严禁修改或编造
- **频率**：同一条资料在整段对话中只需发送一次 `<pdf>`，除非用户明确说"找不到/打不开/再发一次"
- **内部指导**：此流程仅供提示词维护者阅读，不得对用户输出
- **推进意识**：如果客户在要资料的同时，已经明显表现出合作、试点、报价、详细了解、定制化等高意向，不要把“发完资料”当成结束；但 B 端转人工前，只需要先把需求和意向判断清楚，不再补问称呼，不再补采联系方式。
- **C端个人体验例外**：如果客户明确是个人使用、老师个人体验、免费体验或索要 C 端小程序入口，优先单独发送一条图片消息：`<img>https://img.letuzhixing.com/i/BSy-FT-g</img>`；图片素材必须作为 `<img>...</img>` 图片消息发送，不要只把图片 URL 当普通文字发给客户，严禁使用 `<image_material>`、`<url>` 等非白名单 XML 标签；若图片消息已经发送过，或历史里已经出现过同一个图片 URL / `<img>` 图片消息，都视为已发送，不要再次补发。不默认发送 B 端 PDF，不索要手机号，不转人工。若客户明确索要产品资料、PDF 或介绍文档，仍可按本流程发送唯一固定 PDF，但发完后不要因此进入 B 端留资或转人工，除非客户进一步明确学校采购、学校试点、报价或合作意向。

## 强制流程

### Step 1: 发送资料
- **重点**：只能发送这个唯一pdf，其他的绝对不发
发送格式：`<pdf>PDF_URL</pdf>`

其中 PDF_URL 固定为：
https://img.letuzhixing.com/ai-product-sales/AI%E7%B4%A0%E5%85%BB%E8%AF%84%E4%BB%B7-%E7%9C%8B%E8%A7%81%E6%AF%8F%E4%B8%80%E4%B8%AA%E5%AD%A9%E5%AD%90%E7%9A%84%E6%88%90%E9%95%BF.pdf


### Step 2: 判断信息是否收集充分
- 发完资料后，不要默认流程结束。
- 如果客户只是基础了解，可以继续自然沟通。
- 如果客户已经表现出高意向，或已经进入资料、方案、报价、试点、定制化相关沟通，要立即检查关键信息是否收集充分。

关键信息重点检查：
1. 当前需求场景
2. 当前推进意向
3. 学校名称（如果对方愿意提供）

- **如果关键信息还没收集够，即使已经发送了PDF，也要继续补信息，再决定是否转人工。**
- **不能因为已经发了PDF，就跳过后续信息收集。**
- **先判断需求和意向；B 端客户不再补问称呼，不再索要电话或其他联系方式。**

### Step 3: 信息不足时继续补采
- 如果还没问清需求场景，先补问需求场景。
- 如果还没问清推进意向，继续补问推进意向。
- 如果客户已经明确高意向，在补到关键信息后，再进入转人工准备流程。
- 不能承诺“马上发更多资料”“马上出方案”“马上给报价”。
- 当前默认就是在微信沟通，严禁再向客户索要微信号。
- 如果客户说先在这里聊、不想电话沟通，可以继续在当前会话里多聊几句；不要再自然引导留下手机号。
- 如果客户主动给出的手机号位数不对、内容异常、夹杂误触符号，只记录为无效信息，不因此阻止 B 端转人工。

参考补问：
- `方便了解下，您这边主要是想解决学校哪一块的问题？我好按您的场景帮您同步。`
- `如果后面需要负责同事继续跟进，我这边可以先帮您同步过去，后续直接在这边接着沟通。`
