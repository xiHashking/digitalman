# 知识库与提示词更新流程

这条分支只处理知识库、公司背景、数字员工话术和回答边界。Live2D、人物素材和渲染逻辑不属于本分支范围。

## 你要新增一份资料时

先把文件放到 `knowledge_sources/` 中合适的分类目录，再告诉我四件事：

1. 文件用途：标准 QA、产品介绍、建设方案、政策资料、公司背景、销售话术还是回答边界。
2. 适用产品：AI 素养评价、教师发展评价、宣传招生就业，或通用公司资料。
3. 使用范围：可以直接对外播报、只能作为内部参考，还是只允许人工确认后使用。
4. 资料优先级：替换旧口径、补充旧口径，还是仅作为低优先级参考。

文件名和目录名尽量使用明确的中文产品名，避免 `new.md`、`final2.md`、`最新版本.md` 这类无法判断用途的名称。

## 新增 QA 的格式

当前检索器识别以下格式：

```markdown
### Q1：用户可能的标准问法
同义问法和语音变体可以写在问题下面。

**A：** 标准回答。后续段落会继续归入这条答案，直到下一个 Q 或标题。
```

QA 文件应放在三个产品 QA 目录之一：

- `02_aisales_product_knowledge/AI素养评价产品QA/`
- `02_aisales_product_knowledge/教师发展评价系统常见场景QA/`
- `02_aisales_product_knowledge/AI宣传招生就业系统常见QA/`

新增 QA 时不要把价格、部署周期、接口能力、效果数字和案例承诺写成没有依据的确定事实。需要保留但尚未确认的内容，单独标记“待确认”，不要混入标准答案。

## 新增普通知识文档

产品介绍、建设方案和政策资料放到对应产品目录下，使用 Markdown。长文档按主题和二级标题拆分，标题要包含产品或主题，便于检索。运营 SOP、CRM 规则和内部流程默认放到内部参考目录，不直接作为对客资料。

## 新增或修改提示词

- 曹老师身份、销售风格和对话流程：修改 `03_digital_employee_strategy/main_prompt.md` 或对应 `skills/` 文件。
- 产品政策、公司背景和回答边界：修改 `04_editable_prompts/02_ai_literacy_product_policy.md`、`03_company_background.md`、`04_answer_boundaries.md`。
- 语音表达、字数和格式：修改 `00_voice_system_prompt.md` 或 `05_voice_output_rules.md`。
- 固定规则回复：修改 `06_deterministic_reply_templates.md`，并明确告诉我需要同步代码规则。

提示词文件和知识文档是不同层级：提示词规定怎么回答，知识库规定可以回答什么事实。新增事实优先放知识库；只有改变行为、语气、边界或格式时才改提示词。

## 我会怎样把资料接入项目

收到你修改后的目录后，我会按以下顺序处理：

1. 检查文件编码、重复内容、冲突口径和是否混入内部指令。
2. 判断文件属于 QA、普通文档、策略提示词、公司背景还是回答边界。
3. 校验 QA 是否被当前解析器识别，检查问题、答案和变体是否能独立检索。
4. 把运行时读取路径统一指向本目录，移除对 Downloads 和外部 worktree 的隐式依赖。
5. 将需要动态加载的提示词从 Python 硬编码中拆出，并保留安全的默认回退。
6. 用代表性问题、变体问题、未知问题和边界问题做离线回归测试。
7. 检查日志中的命中范围、证据引用、最终回答和响应时间。
8. 只在验证通过后重启后端；知识库或提示词变化不需要重新打包平板 App。

## 每次更新的交付内容

每次接入都会说明：哪些文件生效、哪些文件被排除、覆盖了哪些旧口径、测试了哪些问题、是否需要重启，以及是否存在待确认事实。没有通过校验的文件不会直接进入对客回答链路。
